## State shape

`ChatRoomStateV1` (`common/src/room_state.rs:26`) — `#[composable]` with 8 fields (order load-bearing, `apply_delta` respects it):

```rust
pub struct ChatRoomStateV1 {
    pub configuration: AuthorizedConfigurationV1, // owner-signed, versioned (configuration_version)
    pub bans: BansV1,                             // banned MemberIds
    pub members: MembersV1,                       // member graph: who invited whom
    pub member_info: MemberInfoV1,                // nicknames/metadata, self-writable
    pub secrets: RoomSecretsV1,                   // encrypted room secrets, private rooms
    pub recent_messages: MessagesV1,              // windowed, capped by configuration.max_recent_messages
    pub upgrade: OptionalUpgradeV1,               // Option<UpgradeV1 { owner_member_id, version, new_chatroom_address: Hash }>
    pub version: StateVersion,                   // format version, serde(default)
}
```

`ChatRoomParametersV1 { owner: VerifyingKey }` — owner VK pins room; `owner_id() -> MemberId` is `VerifyingKey.into()`.

Each sub-state is its own module with `summarize/delta/apply_delta/merge/verify` generated by `freenet_scaffold_macro::composable`. See `common/src/room_state/{configuration,ban,member,member_info,secret,message,privacy,upgrade,version}.rs`.

## Four functions

### validate_state (`room-contract/src/lib.rs:17`)
- Allows empty bytes (not-yet-initialized). Otherwise `ciborium::from_reader::<ChatRoomStateV1>` + `from_reader::<ChatRoomParametersV1>`; delegates to `state.verify(&state, &params)` (scaffold `ComposableState::verify`). Returns `InvalidState` on failure, `Deser` on CBOR error.

### update_state (`room-contract/src/lib.rs:39`)
- Deserializes `params` + current `ChatRoomStateV1`. Folds each `UpdateData`:
  - `State(bytes)` → deserialize `ChatRoomStateV1` + `state.merge(&state.clone(), &params, &incoming)` (scaffold merge = per-field CRDT join)
  - `Delta(bytes)` → deserialize `ChatRoomStateV1Delta` + `state.apply_delta(&state.clone(), &params, &Some(delta))`
  - `RelatedState` → TODO no-op (river single-contract)
  - `_ => unreachable!()` — skips unknown variants
- Serializes merged state via `into_writer` → `UpdateModification::valid`. **Idempotent**: incoming values re-merged via `max`/set-union per field; replay is no-op.

### summarize_state (`room-contract/src/lib.rs:86`)
- Empty state → `StateSummary([])`. Otherwise `state.summarize(&state, &params)` (scaffold structural summary — per-field digests) → CBOR `StateSummary`. **Not a scalar**: structural, catches compensating divergence that a total would miss (skill §3).

### get_state_delta (`room-contract/src/lib.rs:105`)
- Deserializes `state` + `params` + `StateSummary` (CBOR `ChatRoomStateV1Summary`). Calls `chat_state.delta(&chat_state, &params, &summary)` → scaffold per-field diff (only lagging keys/fields). Serializes via CBOR → `StateDelta`. Empty delta when peer is converged.

## Merge laws

Scaffold provides the join-semilattice per sub-state:
- `configuration`: owner-signed LWW by `configuration_version` (higher wins, signature-checked)
- `bans/members/member_info/secrets/messages`: set/map union with per-element signature + monotonic version/sequence; `messages` windowed by `(timestamp, id)` desc truncated to `max_recent_messages`
- `upgrade`: owner-only LWW (once set, pins new address)
All are commutative/associative/idempotent. `update_state` folds them in any order; order-independent.

## Scaling

State = O(members + bans + member_info + messages_window + secrets). Message window caps at `max_recent_messages` (default 100 in `AuthorizedConfigurationV1`), so clicks beyond window do not grow state — O(1) per message burst. Keeping per-member info is Ω(members) (skill §5). Whole-state deltas avoided; per-field deltas send only lagging fields (e.g. one new message ≈ one entry, not entire room).

## Trust & upgrade

- Contract key = `Blake3(WASM_bytes || owner_VK_bytes)`. Forking contract → different key (isolated room). Forking client → same key, can submit inflated but signature-checked updates (skill §6). All mutations are ed25519-signed; any peer can verify without hosting secrets.
- Private rooms: `secrets` holds encrypted room secrets + rotation; metadata (existence, member count, invite tree) is still observable (see River README).
- Upgrade: `OptionalUpgradeV1` lets owner sign a pointer to a new contract address. New WASM → new key → migration copies state; old contract stays readable. Partially implemented (see `river#59`).

## Mapping to freenet-contract-design

- §0 pure reducer: `update_state` is pure `merge(verify(params))`.
- §1 reconcile wall: avoided via non-empty structural `ChatRoomStateV1Delta` + structural summary.
- §2 idempotent: `merge` reads from `data`, not `state + 1`.
- §3 four-function wiring: scalar would hide divergence; structural summary + per-field delta keeps `summary_size*2 < state_size` heuristic and byte-equality anti-entropy (0.2.101) working.
- §4 G-counter: not a counter app; membership is a signed set (analogous pattern with per-member slots).
- §6 choose-2: scale+reliability at O(members), anti-cheat via ed25519 signatures (no global PoW).
