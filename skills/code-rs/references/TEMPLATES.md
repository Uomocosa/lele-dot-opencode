## Card rules

- **Header:** `#### Block N. <crate>/<path>.rs[, <crate>/<path>.rs…]` — every file the block
  creates or touches, each prefixed with its crate. No item name, no `(new)`, no Kind (fn vs
  type is visible in the definition fence; bevy systems live in `bevy_systems/`).
- **Description:** plain paragraph right after the header, ≤ 3 lines, no label. For a changed
  item, line 1 says what it did before.
- **Names:** numbered list, at least 3, each `name` + one-line tradeoff; ✅ on the chosen one.
- **Definition:** one ` ```rust ` fence, first line `// definition (new|changed)`, then the
  item's full signature (or struct/enum shape) with the CHOSEN names.
- **Generated by / Used by:** ONE ` ```rust ` fence PER ENTRY — never several entries in one
  fence. Inside each fence:
  1. `// <path>:<line>` or `// Block N` (append `(changed)` if that caller changes).
  2. The outer fn's FULL signature, opening `{`.
  3. The call line(s) touching this block, annotated with every argument's name AND type,
     plus `-> <output>` when not unit:
     `put_history(swarm: &mut Swarm<Behaviour<Payload>>, id: &RoomHistoryRecordId, data: Vec<u8>);`
     Methods keep the receiver: `lobby.merge(incoming: Lobby);`. Not valid Rust — on purpose.
  4. Closing `}`.
  For "Generated by" the outer fn is the producer and the inner line is where it builds the
  value. A type held as a field: `struct Outer { field: ThisType, .. }` in its own fence.
  Omit "Generated by" for fns. Empty list → a plain line `- none yet` (no fence).
- **Signatures:** parameter names mandatory; no module paths; keep `&`, `&mut`, `Option`,
  `Result<T, E>`, `impl Fn(..)`, lifetimes only if needed; never `-> ()`.
- No code bodies beyond the call line, no BEFORE/AFTER diffs, no code-size review section,
  no future callers.
